# Codex Friends

在 Telegram 中查看本机 Codex 任务、回复任务、处理审批和问题。直接使用 Codex 官方共享 app-server 和会话队列，适用于 VS Code Terminal 和 iTerm2 中正常启动的 Codex CLI。无需 tmux，无需 OpenAI API Key；只依赖 ws 库处理官方 Unix socket 的 WebSocket 协议。

要求：Node.js 24.5+、支持共享 app-server daemon 的 Codex CLI、已运行的共享 daemon。`--no-daemon`、不同 CODEX_HOME、另一台电脑上的任务不属于当前共享服务。

## 启动

在自己的终端里确认 `.zshrc` 中是 `export TELEGRAM_TOKEN=...`。Token 不需要发到聊天，也不会存入本项目的文件。已公开的旧 Token 建议在 BotFather 用 `/revoke` 更换。

```sh
cd ~/codex-friends
npm ci
npm run check
npm start
```

启动命令自动加载 `.zshrc`，在独立后台进程中运行并将输出写入日志。重复启动会显示“已经运行”，不会启动第二个机器人。意外退出或被强制终止后，重新执行 `npm start` 即可，旧 PID 记录会自动处理，配对和会话名字保持不变。

## 启动、停止和状态

先在公司电脑的终端执行 `cd ~/codex-friends`，然后：

| 操作 | 命令 |
| --- | --- |
| 后台启动／被杀掉后恢复 | `npm start` |
| 查看进程、配对和连接情况 | `npm run status` |
| 手动停止桥接 | `npm stop` |
| 重新启动 | `npm run restart` |
| 持续查看日志，Ctrl+C 退出查看 | `tail -f .local/bridge.log` |
| 在当前终端运行以调试，Ctrl+C 停止桥接 | `npm run foreground` |

状态查询不需要 Token 或联网；它检查实际进程身份和最近的连接记录。状态会显示当前进程的 PID、运行时长、是否配对、当前会话数、最近 Telegram 通信和 Codex 刷新时间、最近错误及日志位置。

Codex 后台断开或请求超时后，桥接保持运行，每 15 秒尝试重新连接并恢复会话订阅；不会重发指令或审批。旧连接的审批卡片会过期，请用 `/pending` 查看重连后重新取得的请求。后台中残留的失效会话会单独跳过，其余会话正常刷新。Telegram 临时网络故障会自动重连；发送失败的审批和问题通知会自动退避重试，在轮询恢复和每 15 秒的检查中尝试补发。成功送达的卡片不自动重复发送，已解决、已断开会话和已回答的问题会取消排队补发。网络超时无法确认 Telegram 是否收件时，补发可能出现重复卡片，但同一请求的批准仍只提交一次；`/pending` 可手动重显。Token 失效或有另一个程序同时接收该机器人的消息时会退出并记录错误。


Telegram 连续两次网络错误或 5xx 后，后续请求自动切换到系统 `/usr/bin/curl` 兜底：每次请求建立独立连接，沿用现有代理，避免长时间复用旧代理连接。每五分钟通过一次正常轮询探测 Node fetch，成功后自动切回。轮询等待 10 秒，请求最长 20 秒；按钮提示回执异步发送，失败不阻塞批准提交。发送失败的消息不在 HTTP 层立即重放，审批通知由上述待处理队列补发。`npm run status` 显示当前通道与最近切换原因。Token 和请求正文仅通过 curl 的 stdin 传入，不写临时文件、不出现在进程参数中。

这两种连接方式共用同一个代理出口，不能解决代理服务完全断网、电脑睡眠或手机 Telegram 无法联网的问题；这种情况需要恢复网络。需要跨平台兜底时，应另外接入国内可达的消息渠道或私人 VPN/SSH 通道。

查看 `.local/bridge.log` 中的配对指令，在三十分钟内向自己的机器人私聊发送 `/pair <配对码>`。配对码只用于首次绑定，机器人仅接受绑定的 Telegram 用户在绑定私聊中的操作；群聊和其他用户的任务控制消息不会执行。未绑定时，私聊 /start 或错误的 /pair 会收到不包含任务信息的配对说明。

如果刚刚编辑 `.zshrc`，重新打开终端，或执行 `source ~/.zshrc` 后启动。支持 Node 原生环境代理：可通过 `HTTPS_PROXY` / `https_proxy` 使用已有网络代理。

## Clash 日本节点自动切换

使用 Clash Verge Rev / Mihomo 本机控制接口，配置路径默认取 `~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/clash-verge.yaml`。控制密钥每次从原配置读取，不复制、不输出，控制请求通过 Node 原生 HTTP 直连回环接口，避免被 VPN 代理绕走。

```sh
npm run vpn -- status   # 当前节点、是否启用、最近探测结果
npm run vpn -- check    # 只检测当前节点到 Telegram，不切换
npm run vpn -- enable   # 启用自动巡检，并保存原选择
npm run vpn -- disable  # 停用，保留当前节点
npm run vpn -- restore  # 停用，并恢复启用前的选择
```

启用后由桥接进程每 45 秒检测 `🚀节点选择` 实际使用的日本节点。用 Mihomo 官方 `/proxies/{name}/delay` 接口检测 `https://api.telegram.org`，连续两次失败后，每批最多三个节点，寻找组内可用的具体日本节点并通过官方选择接口替换；健康时不切换，切换冷却三分钟，全部不可用时保留原选择。探测只说明该时刻 Telegram 公共 HTTPS 地址可达，不保证所有 Telegram 请求或手机端连接都成功。

当前 Telegram 和其他规则共用 `🚀节点选择`，因此切换也会影响使用该组的其他新连接。不会改订阅、路由规则或系统代理。选好节点后，只关闭该组下已识别的 `telegram.org` / `cdn-telegram.org` 域名连接，使其重连；其他既有连接保持运行。用 IP 或其他域名建立的 Telegram 连接不在清理范围内。切换前再次核对选择，避免覆盖探测期间的手动修改；手动选非日本节点时自动暂停。CLI 的 `disable` 可以离线停用巡检，`restore` 需要 Clash 控制接口可用。

首次配置默认不启用；`enable` 后在桥接运行期间持续巡检，包括 Telegram 尚未成功连接的启动阶段。已运行的旧版本需要 `npm run restart` 加载此功能。设置与结果保存在被 Git 忽略的 `.local/clash-guard.json`、`.local/clash-status.json`，可在 `npm run status` 中查看最新健康状态。

## 手机使用

在机器人的私聊中输入 `/`，Telegram 会显示已注册的指令与中文说明；也可点击输入框旁的菜单按钮。菜单在首次配对和程序启动时自动注册，仅显示在已配对的私聊中。

- `/tasks`：只列出能确认仍在 VS Code Terminal、iTerm2 等终端中打开的会话，点按钮选择任务。空闲但终端仍打开的会话会保留，后台残留会话隐藏。

- `@c1 继续`：直接给指定会话发送消息。每个会话的名字显示在 `/tasks` 中，名字在重启后保持不变。
- `/alias c1 登录`：给会话取一个好记的名字，之后可发 `@登录 继续`；原来的 `@c1` 仍然有效。
- `@c1 @c2 各自汇报进度`：向明确指定的多个会话发送相同消息。任何名字无效或未连接时，整条消息不发送。
- 直接发送文字：给当前选中的任务发送指令。执行中的任务使用 Codex 原生队列，空闲任务开始下一轮。
- 消息回执区分已被 Codex 接收、仍在队列、已启动处理和执行状态未确认。终端与桥接同时接收消息时，通过消息标识核查对话记录，避免重复启动或重发。
- 回复任务通知：发送给该通知对应的任务，避免多个任务之间混淆。
- `/view`：查看选中任务最近对话。
- `/pending`：再次显示等待中的请求。
- 审批：默认看清具体操作后点“批准一次”或“拒绝”。权限类批准只作用于当前轮次。
- `/autoallow c1 on`：为指定主会话及其子任务开启自动允许，包含当前等待及后续的命令、文件、权限、MCP 工具审批。`/autoallow c1 off` 同时关闭主会话与子任务的自动允许；`/autoallow c1` 查看该会话状态，直接 `/autoallow` 列出已开启的会话。支持别名与 `@c1` 写法。也可在 `/tasks` 点进会话后使用自动允许按钮。
- MCP 工具授权（如 REA、cua_repl）：显示服务、操作和调用参数，可点“允许本次”“拒绝”或“取消”；Codex 明确提供会话授权时，也显示“允许本会话”。该选项只记住对应工具在当前 Codex 会话中的授权。通用 MCP 表单、登录和用户验证仍在电脑端处理。
- 问题：点击选项或使用 Telegram 的“回复”；多道问题依次回答。秘密输入仍在电脑端处理。

`/tasks` 回复失败后会自动退避重试，并在每次补发前重新检测终端会话；待回复标记保存在本地，桥接重启后继续补发。并发的列表请求会合并，成功后停止重试；网络超时无法确认收件时，仍可能出现重复列表。这里只补发列表，不重放任务指令或审批。`npm run status` 可查看最近一次列表送达 Telegram 的消息编号与时间。

自动允许默认关闭，只有已配对用户能针对某个主会话开启。设置绑定会话 ID，保存在本地，桥接重启或断线重连后继续生效；同目录新建、分叉出的其他独立会话不会继承，修改别名也不会改变绑定。由该会话派生的子任务与更深层子任务，通过 app-server 的 `parentThreadId`（或历史 `thread_spawn.parent_thread_id`）关联主会话，遵循主会话的开关；不信任审批参数中自称的父会话。无法确认归属、父信息冲突或形成循环的子任务不自动继承。

开启后即使 Telegram 暂时断网，桥接仍会响应该会话及子任务的已知审批；电脑与桥接必须保持运行。每次只提交当前操作的 Allow，不写永久规则、不使用工具的原生会话授权，因此关闭后新审批恢复手动确认；已批准的操作和当前轮次权限不撤销。问题、登录、验证、通用表单、未知审批和未提供 Allow 的请求仍需人工处理。自动允许的请求写入日志和 `npm run status`，不再逐条发审批卡片；`/tasks` 标记已开启会话。原有卡片在自动处理后过期。

桥接每 15 秒发现并订阅主会话的子任务，重启或重连时重订阅并接收仍待处理的审批。子任务不作为独立好友显示，也不逐条发送完成通知；审批和问题通知显示“@主会话 / 子任务 名字”，回复普通通知时仍路由到主会话。`/tasks` 的主会话状态会汇总子任务等待审批/回答的标记；`npm run status` 显示子任务订阅数和等待审批的子任务。Computer Use 的应用访问授权（如 Microsoft Edge、Keynote）在当前版本下仍属于带 `mcp_tool_call` 标记的普通空表单审批，按同一规则处理。

程序自动关注共享服务中已加载的主任务，每 15 秒发现新任务。默认发送审批、提问和本轮结束通知。不会创建任务、修改 Codex 的审批配置、自动升级／重启 Codex daemon。

`/tasks` 在每次调用时读取 macOS `ps` 中带 TTY 的 Codex 进程，再用 `lsof` 的回环监听端口与官方 `mcpServerStatus/list` 返回的 `codex_tui.httpOrigin` 对应。不会按空闲状态、最近活动时间或工作目录猜测，也不读取终端文字、进程参数或环境变量。`thread/loaded/list` 只表示后台内存中加载，关闭终端后仍可能残留，桥接自身订阅也可能使其保持加载。过滤仅改变列表，已有审批订阅、`@名字` 路由和后台任务继续工作。该端口字段依赖当前 Codex 实验协议；旧版 CLI、尚未进入具体会话的选择器、TUI 信息未同步或不属于当前共享服务的进程，可能暂时无法对应而被隐藏。`npm run status` 会显示最近一次 `/tasks` 检测的数量与时间。

```sh
zsh ~/codex-friends/scripts/stop.zsh
```

停止桥接不会停止 Codex。后台进程可在关闭终端后保持运行，但电脑重启后需要再次启动；电脑必须开机、联网且保持唤醒。桥接未运行时，Telegram 消息暂时不能转交给 Codex。启动、停止和状态命令在电脑终端执行。

## 状态和边界

`.local/state.json` 保存绑定用户、会话名字、自动允许设置、最近消息路由、已消费更新位置和配对状态。文件权限 600，目录权限 700。不要公开此目录。审批按钮绑定到当前连接的具体请求，已解决请求或重启前的按钮不能再次使用。

Codex app-server 属于实验接口，后续 CLI 更新可能改变协议。共享服务之外的独立窗口不能直接接入。对既有等待请求能否补发，以实机验证为准；程序不根据“yes”文字猜测批准。当前支持官方命令、文件和权限审批、requestUserInput，以及带 Codex MCP 工具审批标记的空表单 elicitation。其他交互提示会要求电脑端处理。

状态和日志中的“交互请求卡片”表示 Telegram 返回了带操作按钮的消息；“请求通知（无按钮）”仅表示提示消息发送成功。

测试：`npm test`。只读检查：`npm run check`，不发送 Telegram 消息、不向 Codex 发任务指令。
